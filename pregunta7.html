Bases de Datos II · Pregunta 7

DBaaS: una base de datos gestionada, no una cuarta capa universal

«El modelo de Base de Datos como Servicio (Database as a Service, DBaaS) entrega entornos virtualizados con elasticidad bajo demanda, backups automáticos y abstracción de hardware. Analice la frontera técnica que separa a una arquitectura DBaaS respecto de las capas de infraestructura (IaaS), plataforma (PaaS) y software (SaaS) en el ciclo de vida de un sistema de información, destacando las ventajas e inconvenientes en términos de vendor lock-in y control del sistema.»

Hoja «Bases de Datos II — Arquitecturas BD vs. Arquitecturas SI» (16/11/2026), pregunta 7.

Tesis: , y son modelos amplios de servicio que difieren en cuánto administra el proveedor y cuánto el cliente. es una oferta especializada de base de datos gestionada, que suele clasificarse como servicio administrado dentro del ámbito PaaS; su nombre comercial y sus responsabilidades concretas varían según el proveedor y el plan.

En pocas palabras: en la nube puedes alquilar máquinas (IaaS), un lugar donde correr tu programa (PaaS) o un programa ya hecho (SaaS). DBaaS es alquilar una base de datos que otro mantiene funcionando. Pero tus tablas, tus consultas y la protección de tus datos siguen siendo tu responsabilidad.

Cuatro ofertas, una pregunta: ¿quién administra qué?

IaaS · infraestructura

El proveedor administra centro de datos, hardware y virtualización. El cliente configura y administra el sistema operativo, instala el motor de BD, aplica sus parches, diseña el esquema y se encarga de aplicaciones, políticas y respaldos (salvo que contrate servicios adicionales).

Ejemplo: una máquina virtual donde el equipo instala PostgreSQL por su cuenta.

PaaS · plataforma

El proveedor administra infraestructura, sistema operativo y entorno de ejecución. El cliente desarrolla y despliega su aplicación y gestiona código, datos y configuraciones.

Ejemplo: una plataforma administrada donde se despliega la API de facturación y stock. Una plataforma para ejecutar código no es lo mismo que una base de datos gestionada.

DBaaS · base de datos gestionada

El proveedor gestiona el aprovisionamiento y la operación del motor según el contrato (parches, backups automáticos, disponibilidad, opciones de escalado). El cliente sigue a cargo del modelo de datos, las consultas, los permisos de acceso, la clasificación de los datos, la configuración de seguridad, los costos y la recuperación que necesita.

Matiz: no todos los DBaaS ofrecen escalado automático, backups ilimitados, alta disponibilidad o migración sin costo; depende del plan.

SaaS · software

Una aplicación terminada para usuarios. El proveedor opera la aplicación y su infraestructura; el cliente administra el uso, los usuarios, sus datos, la configuración y las obligaciones que le correspondan.

Ejemplo: un CRM web ya construido. Quien lo usa no necesita escribir SQL.

    Balance de DBaaS: control frente a comodidad

    Ventajas

    • Puesta en marcha rápida.
    • Menor carga operativa (instalación, parches del motor).
    • Copias de seguridad y monitorización administradas, cuando el plan las incluye.
    • Elasticidad según el servicio contratado.
    • Disponibilidad y mantenimiento gestionados.

    Inconvenientes

    • Costo recurrente y por consumo.
    • Restricciones de configuración y de extensiones.
    • Dependencia de APIs propietarias y herramientas del proveedor.
    • Límites regionales y latencia.
    • Costos de salida y transferencia de datos.
    • Dependencia contractual y del .

    Vendor lock-in: dificultad técnica, económica u operativa para cambiar de proveedor. Se reduce con SQL estándar, formatos abiertos, migraciones documentadas, backups exportables, pruebas de restauración, una capa de abstracción de acceso y evitando servicios exclusivos cuando no hacen falta. No se elimina por completo.

    Respuesta de examen

    Respuesta completa para examen

    DBaaS es un servicio administrado especializado en bases de datos: el proveedor se encarga de gran parte del aprovisionamiento y operación del motor, mientras el cliente sigue diseñando el esquema, administrando accesos, realizando consultas y protegiendo sus datos. Se diferencia de IaaS porque, en una máquina virtual, el cliente normalmente instala y mantiene el DBMS; de PaaS porque este término abarca plataformas gestionadas para ejecutar aplicaciones, mientras DBaaS se concentra en el servicio de datos; y de SaaS porque SaaS entrega una aplicación completa lista para usar. DBaaS suele ubicarse dentro de los servicios gestionados de tipo PaaS, no como una capa universal adicional. Su principal ventaja es reducir tareas operativas y acelerar el despliegue, con capacidades de backup, escalado y disponibilidad que dependen del plan contratado. A cambio, disminuye el control sobre el sistema subyacente y puede aumentar el vendor lock-in por funciones propietarias, costos de salida y dificultad de migración. Conviene evaluar la responsabilidad compartida y mitigar la dependencia con estándares abiertos, respaldos exportables y planes de migración. En el contexto comercial, contratar el DBMS de facturación como DBaaS reduce la carga del equipo de TI, pero la comercializadora sigue respondiendo por el esquema de facturas y clientes, los permisos sobre datos de ventas y la recuperación de sus asientos; por eso conviene negociar exportaciones en formato abierto y ensayar la restauración.

    Resumen oral de 45 segundos

    IaaS, PaaS y SaaS se diferencian por cuánto administra el proveedor. En IaaS recibo máquinas virtuales e instalo yo el motor; en PaaS la plataforma ejecuta mi código; en SaaS uso una aplicación terminada. DBaaS es una base de datos gestionada, normalmente dentro de PaaS, no una cuarta capa: el proveedor opera el motor y, según el plan, backups y escalado; yo respondo por esquema, consultas, permisos y protección de datos. Gano rapidez y menos carga operativa, pero pierdo control y arriesgo vendor lock-in, que mitigo con estándares abiertos y respaldos exportables. En mi comercializadora: el proveedor opera el motor de facturación; yo respondo por facturas y clientes.
