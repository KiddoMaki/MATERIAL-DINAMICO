Bases de Datos II · Pregunta 2

Cliente-servidor no vive «dentro» de la base de datos

«El modelo Cliente-Servidor (en 2 o 3 capas) describe la separación funcional entre el procesamiento interactivo del cliente (front-end) y los servicios centrales del servidor (back-end). Explique por qué resulta un error conceptual clasificar a Cliente-Servidor como una arquitectura interna de almacenamiento y procesamiento de BD, y contraste este modelo de despliegue de software con las arquitecturas físicas de hardware en DBMS paralelos como Shared Memory, Disk y Shared Nothing.»

Hoja «Bases de Datos II — Arquitecturas BD vs. Arquitecturas SI» (16/11/2026), pregunta 2.

Tesis: cliente-servidor es un modelo de distribución de responsabilidades y comunicación entre componentes de una aplicación. Shared Memory, Shared Disk y Shared Nothing son arquitecturas internas de recursos de cómputo de un paralelo. Son ejes de análisis distintos, pueden coexistir y no son alternativas excluyentes.

En pocas palabras: cliente-servidor responde «¿quién le pide qué a quién?» dentro de una aplicación. Shared Memory, Shared Disk y Shared Nothing responden «¿cómo se reparten la memoria y los discos las máquinas que forman el motor de base de datos?». Son dos preguntas diferentes, y una misma aplicación puede tener respuesta para las dos.

Idea clave en 20 segundos

Cliente-servidor = cómo se reparte el trabajo de una aplicación en capas (presentación, lógica, datos).

Shared Memory / Disk / Nothing = cómo reparte el motor de BD por dentro sus CPU, memoria y discos.

Son dos niveles distintos, así que se combinan: el sistema de facturación de una comercializadora (3 capas) puede usar un DBMS shared-nothing.

Dos niveles de análisis

Nivel 1 · Arquitectura del sistema de información

Cliente-servidor de 2 capas: el cliente (interfaz y, según el diseño, parte de la lógica) se comunica con un servidor que presta servicios de datos, por ejemplo un DBMS. Dónde queda exactamente la lógica de negocio varía: puede estar en el cliente o en el servidor (procedimientos almacenados, vistas).

Cliente-servidor de 3 capas: presentación (navegador) ↔ lógica de negocio o (servidor de aplicaciones) ↔ datos (DBMS). El cliente solicita, la API valida y aplica reglas, y el DBMS consulta y persiste. En una comercializadora, la interfaz del vendedor, la API de facturación y el DBMS son esas tres capas: la API comprueba el stock y las condiciones de venta antes de tocar los datos.

Es una decisión de diseño y despliegue de software: separa responsabilidades ( / ) y define protocolos de comunicación (HTTP, protocolo del DBMS).

Nivel 2 · Arquitectura interna de un DBMS paralelo

Shared Memory: varios procesadores acceden a una memoria principal común.

Shared Disk: cada tiene memoria privada, pero todos acceden a un almacenamiento común.

Shared Nothing: cada nodo tiene su propia , y , y se comunican por mensajes a través de la red.

Es una decisión sobre cómo se organizan los recursos de cómputo del motor para ejecutar consultas en paralelo: no dice nada de quién es el cliente ni de cuántas capas tiene la aplicación.

      Respuesta de examen

      Respuesta completa para examen

      Es un error clasificar cliente-servidor como arquitectura interna de bases de datos porque describe la organización funcional de una aplicación y la comunicación entre clientes y servidores, no cómo el DBMS distribuye físicamente sus procesadores, memorias y discos. En dos capas, el cliente interactúa con un servidor que presta servicios de datos; en tres capas, la presentación se separa de la lógica de negocio y del almacenamiento. En cambio, Shared Memory, Shared Disk y Shared Nothing describen cómo un DBMS paralelo organiza recursos: memoria común entre procesadores, discos comunes con memorias privadas o nodos con CPU, memoria y discos propios, respectivamente. Estos enfoques no compiten entre sí: una aplicación de tres capas puede usar un DBMS shared-nothing en su capa de datos. Por tanto, cliente-servidor pertenece al nivel de arquitectura y despliegue de software del sistema de información, mientras que las arquitecturas compartidas o no compartidas corresponden al nivel físico de procesamiento del motor de base de datos. En el contexto comercial: la terminal del vendedor, la API de facturación y el DBMS son las tres capas de la aplicación; que el motor sea shared-nothing con la tabla de facturas particionada en varios nodos es una decisión interna de la capa de datos, invisible para la API.

      Resumen oral de 45 segundos

      Cliente-servidor y las arquitecturas paralelas responden preguntas distintas. Cliente-servidor organiza una aplicación: quién pide y quién presta el servicio, en dos capas, cliente y servidor de datos, o en tres, presentación, lógica de negocio y datos. Shared Memory, Shared Disk y Shared Nothing describen el interior de un DBMS paralelo: si los procesadores comparten memoria, si comparten discos con memorias privadas o si cada nodo tiene CPU, memoria y disco propios. Por eso, clasificar cliente-servidor como arquitectura interna de la base de datos es un error de nivel. Además, no se excluyen: una comercializadora de 3 capas puede usar un DBMS shared-nothing con la tabla de facturas repartida.
